CAVEAT: this test-phase agent's shell has no controlling terminal anywhere in its
process ancestry (launchd -> no-mistakes -> claude -> zsh -> bash all show TTY=??).
macOS's /usr/bin/nohup calls __vprocmgr_detach_from_console before exec (confirmed
via `nm -u /usr/bin/nohup`), which fails with "can't detach from console:
Inappropriate ioctl for device" and exit 127 when no console session exists -
reproduced with a neutral command, `nohup /bin/sleep 5`, no project code involved.
bin/fm-fleet-publish.sh's launch_publisher() shells out to nohup unconditionally
(bin/fm-fleet-publish.sh:803), so `start` cannot spawn a daemon AT ALL in this
exact process context - this is a real, deterministic failure of the shipped
`start` command in this environment, reported separately as a finding.

To still observe the cadence loop's actual behavior end-to-end, the transcript
below was captured with nohup replaced on PATH by a shim that ignores SIGHUP and
execs directly (`trap "" HUP; exec "$@"`), i.e. the same detach contract nohup
promises, minus the one macOS call that needs a console session. This is NOT how
the shipped script runs unmodified in this environment; it isolates whether the
rest of the mechanism (cadence loop, atomic publish, beacon, identity, stop) is
correct once launch succeeds. Real producer (bin/fm-fleet-snapshot.sh) was used,
cadence=5s, FM_FLEET_PUBLISH_MIN_CADENCE=1 (the documented test seam).
